# Research: which parts of the Arch NVIDIA setup Fedora still needs

Ticket: itsKontra/ryoku-fedora#196 (parent #193). Researched 2026-10-22.

This note sorts each piece of NVIDIA behaviour in the Arch edition into one of four outcomes:

- **Packaging handles it**: Fedora's NVIDIA packages, or the upstream driver defaults, already do it.
- **Needs Ryoku**: no Fedora package does it, so Ryoku would have to.
- **Does not apply**: the mechanism is specific to Arch (pacman, mkinitcpio, Limine), or Fedora's policy is the opposite.
- **Open**: the evidence does not settle it.

It does not decide what to ship.

Ryoku paths are cited at `fork/fedora/iso` `41821de4e` (the branch this note sits on). Most of the Arch logic is the same as upstream `main`. The `dnf` early exits exist only on this branch.

## What the Fedora edition does today

Fedora stays on nouveau and makes no NVIDIA changes.

- **Shell installer**:
  - `stepDrivers` returns before any vendor script runs (`ryoku-shell-installer/engine.go:2150-2156`).
  - The `nvidia` plan default is forced off for Fedora (`engine.go:275-279`).
  - The "NVIDIA proprietary drivers" toggle is hidden on Fedora (`ryoku-shell-installer/main.go:197`).
- **Driver script**: `nvidia.sh` exits 0 under `dnf` with "Fedora manages NVIDIA drivers and dracut outside this Arch/Void helper" (`system/hardware/drivers/nvidia.sh:152-155`).
- **Kickstart/ISO**: maps `nvidia-utils` and `lib32-nvidia-utils` to nothing (`fedora/packages/translations.tsv:100,150`). `fedora/README.md:87` and `docs/installation-hardware.md:78-79` say NVIDIA stays on nouveau.
- **Doctor** (`ryoku/cli/internal/doctor/reconcile_hardware.go`), on `host.DNF`:
  - Kepler recovery only reports (`:279-284`).
  - Modeset/boot reliability only reports. When the module is not loaded, it gives manual advice: enable RPM Fusion, install `akmod-nvidia`, run `dracut --regenerate-all --force` (`:431-440`).
  - The guard hook reports ok with "Fedora kernel-module packages manage their own update hooks" (`:671-674`).
  - Driver detection counts only `akmod-nvidia` and `xorg-x11-drv-nvidia` (`:335-336`).
  - The sleep-unit reconciler (`:766-805`) has no DNF gate (see row 7).
- **Packaging**:
  - The Fedora `ryoku-desktop` RPM drops `/usr/lib/initcpio` (`fedora/packages/rpm/payload/ryoku-desktop.sh:20`).
  - It still installs every `system/hardware/*/ryoku-*`, including `ryoku-nvidia-guard`, `ryoku-gpu`, `ryoku-gpu-mux` and `ryoku-gpu-lib32`, through the shared hardware glob (`release/packages/ryoku-desktop/payload.sh:355-358`).
  - It also installs `90-ryoku-gpu.rules` (`:403-404`) and `45-ryoku-gpu-mux.rules` (`:565-566`).
- **Display manager**: SDDM, which replaces GDM (`fedora/README.md:20`). The SDDM login-loop failure mode described for Arch carries over unchanged.

## Summary

- **Fedora packaging already covers** most of the list: DRM modeset and fbdev, the nouveau and nova blacklist, PreserveVideoMemoryAllocations and kernel suspend notifiers, runtime D3, GBM and EGL, and PRIME. With RPM Fusion it also covers 32-bit libraries and the nouveau fallback that prevents the login loop.
- **Does not apply on Fedora**: the mkinitcpio and Limine pieces; NVIDIA in the initramfs, where all three Fedora sources deliberately do the opposite; initramfs rebuilds after a driver change; the pacman hook; prebuilt-versus-DKMS selection; the pacman `-Rdd` dance; `nvidia_drm.modeset=1` on the command line.
- **Needs Ryoku**:
  - The VA-API package (row 17). It is broken on this machine now.
  - The Limine-only backlight fix (row 21).
  - Choosing a legacy branch (row 1), if Ryoku installs the driver.
  - A login-loop fallback (row 11) and 32-bit libraries (row 16), but only if negativo17 or NVIDIA's repository is supported instead of RPM Fusion.
- **Open**: nouveau's weight in a dracut image (row 19); the Fedora version of the Kepler/580xx trap (row 12).
